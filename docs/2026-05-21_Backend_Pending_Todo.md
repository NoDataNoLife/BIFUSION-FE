# 백엔드 API 연동 보류 및 해결 내역 가이드

이 문서는 과거 마이페이지 고도화 작업 당시 백엔드 API 스펙이 아직 준비되지 않아 프론트엔드 연동이 막혔던(보류되었던) 부분들과, 어떻게 그것들이 해결되었는지 그 논리 구조를 설명합니다. 프론트엔드에서 특정 기능을 구현하기 위해 백엔드에서 어떤 데이터가 반드시 필요한지 이해하는 데 도움이 됩니다.

---

## 1. [✅ 해결됨] "상태"를 수정하면 "조회" API도 수정되어야 한다

프론트엔드에서 유저의 정보(프로필 사진, 요금제, 전문가 인증 상태)를 서버에 전송하여 성공적으로 변경(업데이트)했다고 칩시다. 그런데 브라우저를 새로고침하면 화면이 다시 과거로 돌아가 버리는 버그가 있었습니다.

### 💡 왜 이런 버그가 발생했을까요?
새로고침을 하면 프론트엔드 메모리가 날아가므로, 화면을 다시 그리기 위해 백엔드의 '유저 정보 조회 API(`GET /api/v1/users/me`)'를 호출합니다.
그런데 이 조회 API의 응답 데이터 안에는 우리가 방금 수정했던 사진 URL, 요금제(BASIC/PRO), 전문가 상태(PENDING) 등의 필드가 **누락되어 있었습니다.**

데이터가 안 오니까 프론트엔드는 어쩔 수 없이 기본값(회색 얼굴, BASIC 요금제, 신청 안 한 상태)으로 화면을 강제로 덮어써 버린 것입니다.

### 💡 어떻게 해결했나요?
백엔드 팀에 요청하여, 정보 조회 API(`GET`)의 응답 DTO에도 수정 가능한 모든 필드를 똑같이 내려주도록 스펙을 맞추어 문제를 완전히 해결했습니다. **"수정(PUT/PATCH)이 가능한 데이터는 반드시 조회(GET) 응답에도 포함되어야 한다"**는 아키텍처 원칙을 배울 수 있는 사례입니다.

---

## 2. [⏳ 대기 중] 프로젝트 초대와 관련된 API 흐름의 끊김

프론트엔드에 "프로젝트 초대 수락/거절" 버튼이 있는데 동작시킬 수가 없습니다.

### 💡 왜 못 만드나요?
초대를 수락하거나 거절하려면 백엔드에 `PATCH /api/v1/projects/{projectId}/invitations/{invitationId}` 라는 API를 찔러야 합니다. 이 주소를 자세히 보면 `projectId`와 `invitationId`라는 고유 번호 2개가 반드시 필요합니다.

그런데 현재 백엔드에는 **"나에게 온 초대장 목록을 보여줘!"** 하는 GET API가 아예 존재하지 않습니다. 목록을 가져올 수가 없으니 프론트엔드 화면에서는 이 유저가 어떤 프로젝트(ID)의 몇 번 초대장(ID)을 받았는지 도무지 알 길이 없고, 따라서 수락 버튼을 누를 때 보낼 데이터가 없는 것입니다.

### 💡 해결을 위한 요구 사항
백엔드 팀에 **"현재 로그인한 사용자가 받은 PENDING 상태의 프로젝트 초대 목록 조회 GET API"**를 새로 만들어 달라고 요청해둔 상태입니다. 이 API가 완성되어야 프론트엔드의 알림 센터와 초대 수락 기능 연동을 마무리할 수 있습니다.

---

## 3. [⏳ 대기 중] 프로젝트를 지울 수가 없다? (참조 무결성)

프론트엔드 화면에 '프로젝트 삭제' 버튼을 만들어 두었지만 아직 연동하지 못했습니다.

### 💡 왜 못 만드나요?
백엔드에 프로젝트 자체를 삭제하는 `DELETE /api/v1/projects/{projectId}` API가 아직 없기 때문입니다.
데이터베이스(DB) 입장에서는 프로젝트 하나를 지우려면 그 프로젝트에 속한 팀원 목록, 얽혀있는 에셋 데이터 등 연관된 데이터를 함께 지워줘야 합니다. (이것을 '참조 무결성' 또는 `ON DELETE CASCADE` 라고 부릅니다.)

백엔드에서 이 DB 관계 설정을 마무리하고 삭제 API를 열어주면, 바로 프론트엔드 버튼에 연동할 수 있도록 대기 중입니다.
