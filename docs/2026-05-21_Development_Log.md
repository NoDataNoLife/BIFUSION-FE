# BIFUSION 프론트엔드 개발 일지: 프론트와 백엔드의 데이터 동기화 문제

이 문서는 2026-05-21에 진행된 마이페이지 프로필 사진 업로드 기능 구현 중 발견된 치명적인 버그와, 이를 통해 배울 수 있는 웹 아키텍처의 중요한 교훈을 설명합니다.

---

## 1. 🚨 유령이 된 프로필 사진 (문제 현상)

마이페이지에서 새로운 프로필 사진을 성공적으로 업로드했습니다. 화면에도 방금 올린 내 얼굴이 예쁘게 잘 나옵니다. 그런데 **새로고침(F5)을 누르거나 다른 페이지에 갔다가 돌아오면, 방금 올린 사진이 사라지고 밋밋한 회색 기본 이미지로 돌아가 버리는 현상**이 발생했습니다.

분명히 업로드에 성공했는데 왜 새로고침만 하면 데이터가 과거로 돌아가 버리는 걸까요?

---

## 2. 🔍 범인 찾기 (원인 분석)

웹 개발을 할 때는 **"정보를 바꾸는 API(수정)"**과 **"정보를 가져오는 API(조회)"**가 짝짜꿍이 잘 맞아야 합니다. 이번 버그는 이 둘의 호흡이 맞지 않아서 생겼습니다.

### 1) 수정을 담당하는 `PUT` API의 노력

프로필 사진을 업로드할 때 프론트엔드는 사진 파일을 백엔드로 보냅니다(`PUT /profile/image`).
그러면 백엔드는 클라우드(S3)에 사진을 안전하게 저장하고, 프론트엔드에게 **"여기 네가 방금 올린 사진 URL 주소야!"** 라고 착실하게 응답을 돌려줍니다.
프론트엔드는 이 주소를 받아서 즉시 화면을 새로운 사진으로 교체합니다. (여기까진 완벽합니다.)

### 2) 조회를 담당하는 `GET` API의 배신

그런데 사용자가 브라우저를 '새로고침'하게 되면 어떻게 될까요? 프론트엔드가 메모리에 들고 있던 데이터(방금 받은 사진 URL)가 전부 초기화되어 날아갑니다.
그래서 프론트엔드는 화면을 다시 그리기 위해 서버에게 **"내 정보 다 다시 줘!"** 하고 조회 API(`GET /api/v1/users/{userId}`)를 호출하게 됩니다.

문제는 여기서 발생했습니다! 백엔드가 넘겨준 내 정보 데이터에는 이름, 소속, 이메일은 다 있는데 **방금 올렸던 '프로필 사진 URL' 항목 자체가 아예 빠져 있었습니다.**

### 3) 결과: "사진이 없네? 그럼 기본 이미지 써야지."

프론트엔드 입장에서는 백엔드가 사진 URL을 안 주니까 "아, 이 유저는 아직 사진을 안 올렸나 보구나" 하고 오해를 하게 됩니다. 그래서 어쩔 수 없이 회색 기본 이미지(`/defaultUserProfile.png`)를 억지로 끼워 넣었던 것입니다.

**[당시 문제가 된 프론트엔드 조회 코드]**

```typescript
// 백엔드에서 사용자 정보(profileData)를 받아옵니다.
const profileData = response.data.data;

set((state) => ({
  user: {
    nickname: profileData.nickname,
    organization: profileData.location,
    // ... 다른 정보는 다 잘 들어오는데 ...
    
    // 치명적 결함! 백엔드에서 이미지 정보를 안 주니, 무조건 기본 이미지로 덮어써버림!
    profileImage: '/defaultUserProfile.png', 
  }
}));
```

## 3. 💡 핵심 아키텍처 교훈

이 사태를 통해 프론트엔드 개발자가 반드시 명심해야 할 교훈을 얻을 수 있습니다.

### Lesson: 상태 일관성 (State Consistency)의 중요성

* 프론트엔드의 전역 상태(Zustand 등)는 브라우저 메모리에 떠 있는 신기루와 같습니다. 새로고침 한 번이면 흔적도 없이 사라집니다.
* 따라서 영원히 변하지 않는 진짜 데이터(Source of Truth)는 무조건 백엔드 데이터베이스에 있습니다. 프론트엔드는 새로고침할 때마다 이 백엔드의 데이터를 조회(GET)해서 신기루를 다시 만들어내는 것뿐입니다.
* 결론적으로 **특정 항목을 수정(UPDATE)할 수 있게 만들었다면, 화면을 처음 그릴 때 쓰는 조회(GET) API에서도 반드시 그 항목을 내려줘야 합니다.** 이 둘 중 하나라도 이가 빠지면, 프론트엔드 화면은 엉망이 됩니다.

---

## 4. 해결 방안 (백엔드 협업 요청)

결국 이 문제는 프론트엔드 코드를 아무리 고쳐도 해결할 수 없습니다. 백엔드 팀에게 아래와 같이 `GET` API 응답 데이터 스펙을 추가해 달라고 요청하여 문제를 깔끔하게 해결했습니다.

**[백엔드에 요청한 응답 데이터 스펙]**

```json
{
    "success": true,
    "data": {
        "userId": 11,
        "name": "조현희",
        "nickname": "hehe",
        // ... (중략) ...
        
        // 백엔드 팀이 새로 추가해 주신 필드!
        // 이제 새로고침해도 이 URL을 받아서 내 얼굴을 띄워줄 수 있습니다.
        "profileImageUrl": "https://.../profile/my_face.jpg" 
    }
}
```
