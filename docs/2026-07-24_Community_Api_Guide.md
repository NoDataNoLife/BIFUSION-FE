# 커뮤니티 API 연동 가이드 및 작업 내역

이 문서는 커뮤니티 파트(전문가 QnA, 데이터셋, 팀원 모집)의 프론트엔드 API 연동을 진행하면서 겪었던 주요 문제들과 이를 어떻게 해결했는지 누구나 이해하기 쉽게 정리한 가이드입니다.

---

## 1. API 요청 주소 중복 오류 (`/api/v1/api/v1/...`) 해결

### 🚨 발생했던 문제

백엔드로 데이터를 요청할 때 자꾸 `404 Not Found` 에러가 발생했습니다. 확인해보니 주소가 `http://localhost:8080/api/v1/api/v1/community/datasets` 처럼 `/api/v1`이 두 번이나 반복해서 들어가고 있었습니다.

### 💡 원인 및 해결 방법

우리 프로젝트는 `src/lib/axios.ts` 파일에 **"앞으로 모든 API 요청에는 기본적으로 `/api/v1`을 붙여서 보내라"**고 전역 설정(`baseURL`)이 되어 있습니다.
그런데 각 컴포넌트에서 API를 호출할 때 습관적으로 `/api/v1/community...`라고 또 적어버려서 중복이 발생했던 것입니다.

**[수정된 코드 예시]**

```typescript
// ❌ 잘못된 예: baseURL 설정이 있는데 또 /api/v1을 붙인 경우
const response = await api.get('/api/v1/community/datasets'); 

// ✅ 올바른 예: /api/v1은 생략하고 그 뒷부분만 적어줍니다.
const response = await api.get('/community/datasets');
```

이 원리를 적용하여 프로젝트 전체의 모든 API 호출 코드에서 중복된 `/api/v1`을 깔끔하게 제거했습니다.

## 2. 가짜 데이터(Mock) 대신 실제 백엔드 데이터 연결하기

### 🚨 발생했던 문제

기존 화면은 백엔드가 없어도 화면이 예쁘게 보이도록 임의로 만들어둔 가짜 데이터(Mock Data)를 사용하고 있었습니다. 백엔드 API가 완성되었으니 이제 진짜 데이터를 가져와야 했습니다.

### 💡 원인 및 해결 방법

리액트에서는 화면의 데이터를 관리하기 위해 **Zustand(상태 관리 라이브러리)**를 사용합니다. `useCommunityStore`라는 창고에 진짜 데이터를 채워 넣는 코드를 작성했습니다.

**[데이터를 불러오는 과정 예시]**

```typescript
// 1. 서버에 데이터를 달라고 요청합니다.
const response = await api.get('/community/datasets');

// 2. 서버가 준 진짜 데이터를 우리 창고(Zustand Store)에 예쁘게 저장합니다.
set({ datasetList: response.data.data.content });
```

이제 화면(컴포넌트)에서는 창고에 있는 `datasetList`를 꺼내 쓰기만 하면, 서버에 새로운 글이 올라올 때마다 화면에 진짜 데이터가 나타나게 됩니다.

## 3. 팀원 모집 "지원하기" 시 400 에러 해결

### 🚨 발생했던 문제

팀원 모집 상세 페이지에서 "지원하기" 버튼을 누르면 서버가 **400 Bad Request(잘못된 요청)** 이라는 에러를 내뿜었습니다.

### 💡 원인 및 해결 방법

백엔드 서버는 데이터베이스에 저장하기 위해 모집글의 ID를 **숫자(1, 2, 3...)**로 기대하고 있었습니다.
하지만 당시 프론트엔드 화면에 떠 있던 글은 가짜 데이터였고, 그 가짜 ID가 `RC-001`이라는 **문자(글자)**로 되어 있었습니다. 서버 입장에서는 숫자가 들어와야 할 자리에 문자가 들어오니 "이해할 수 없는 데이터다!" 라며 에러를 뱉은 것입니다.

가짜 데이터의 ID를 숫자인 `'1'`로 임시 수정해 주어 서버가 올바르게 데이터를 받을 수 있도록 해결했습니다.

## 4. 데이터셋 "사용 가이드" 화면 마크다운(Markdown) 렌더링 적용

### 🚨 발생했던 문제

데이터셋을 올릴 때, 작성자가 파이썬 코드 같은 **"사용 예시"**를 텍스트로 적습니다. 하지만 기존 상세 페이지에서는 이 글자가 그냥 밋밋한 텍스트로만 나와서 코드를 읽기가 너무 불편했습니다.

### 💡 원인 및 해결 방법

백엔드는 작성자가 쓴 텍스트를 그대로 저장했다가 그대로 돌려주기만 합니다. 즉, 화면을 예쁘게 꾸미는 건 순전히 프론트엔드의 몫입니다.
프론트엔드에 `react-markdown`이라는 도구를 설치하여, 백엔드에서 받은 단순한 텍스트를 **깃허브(GitHub) 스타일의 예쁜 코드 블록(색상 하이라이팅 포함)**으로 변환해 주도록 만들었습니다.

**[코드 예시]**

```tsx
import ReactMarkdown from 'react-markdown';
import rehypeHighlight from 'rehype-highlight';

// 단순한 글자(datasetPost.usageExample)를 ReactMarkdown 도구 안에 넣어주면
// 파이썬 코드를 인식해서 자동으로 예쁜 색상을 입혀줍니다!
<ReactMarkdown rehypePlugins={[rehypeHighlight]}>
  {datasetPost.usageExample}
</ReactMarkdown>
```

이제 작성자가 글을 쓸 때 백틱(```) 기호를 사용해 코드를 적으면, 상세 페이지에서 깃허브처럼 완벽한 코드로 보이게 됩니다. 백엔드를 수정할 필요 없이 프론트엔드만으로 멋진 기능을 추가한 대표적인 사례입니다.
