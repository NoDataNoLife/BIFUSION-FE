# Vercel 프론트엔드 실서버 배포 및 백엔드 연동 트러블슈팅

이 문서는 로컬에서 개발하던 프론트엔드(React/Vite)를 Vercel(실서버)에 배포하고, 외부의 백엔드 실서버(EC2)와 연결하는 과정에서 발생했던 대표적인 에러들과 그 해결 과정을 기록한 가이드입니다.

---

## 1. 하드코딩된 백엔드 주소로 인한 연결 실패

### 🚨 발생했던 문제

Vercel에 배포된 프론트엔드에서 구글 로그인 버튼을 클릭했는데, 화면이 `https://bifusion.duckdns.org` (실서버 백엔드)로 넘어가지 않고 `http://localhost:8080/oauth2...` 로 이동하여 에러가 발생했습니다.

### 💡 원인

프론트엔드 코드(Axios 설정 및 리다이렉트 로직)에 백엔드 주소가 `http://localhost:8080`으로 하드코딩되어 있었습니다. 로컬 개발 시에는 문제가 없었으나, 실서버에서도 내 컴퓨터의 8080 포트를 찾으려 하니 문제가 발생한 것입니다.

### 🛠️ 해결 방법 (동적 환경 변수 주입)

코드를 수정하여 외부에서 주입해 주는 **환경 변수(`VITE_API_URL`)**를 최우선으로 바라보도록 변경했습니다.

```typescript
// src/lib/axios.ts
// 환경 변수가 있으면 그걸 쓰고, 없으면(로컬 환경) 빈 문자열을 써서 프록시(/api/v1)를 태웁니다.
const SERVER_URL = import.meta.env.VITE_API_URL || '';

export const authApi = axios.create({
  baseURL: `${SERVER_URL}/auth`,
});
```

그리고 Vercel 대시보드(Settings > Environment Variables)에 들어가서 `VITE_API_URL = https://bifusion.duckdns.org` 값을 직접 넣어줌으로써, 실서버 환경에서만 완벽하게 백엔드 주소를 갈아 끼우는 데 성공했습니다.

---

## 2. 구글 로그인 시 "502 Bad Gateway" 에러 발생

### 🚨 발생했던 문제

Vercel 설정 완료 후 구글 로그인 버튼을 눌렀더니, 주소창은 `https://bifusion.duckdns.org`로 잘 넘어갔으나 화면에 덩그러니 `502 Bad Gateway (nginx/1.24.0)` 에러가 떴습니다.

### 💡 원인 (프론트엔드 탓이 아닙니다!)

502 에러는 프론트엔드 코드가 백엔드의 문지기(Nginx)까지는 아주 잘 도달했다는 뜻입니다. 하지만 Nginx가 뒤에 있는 진짜 뇌(Spring Boot 프로그램)에게 요청을 넘겨주려고 보니, **Spring Boot 서버가 꺼져 있어서 응답을 받지 못한 것입니다.**
주로 백엔드 개발자가 도메인 연결이나 HTTPS 적용 작업을 하느라 서버를 잠시 내렸거나 뻗었을 때 자주 발생합니다.

### 🛠️ 해결 방법

백엔드 개발자에게 "EC2에 Nginx는 살아있는데 Spring Boot가 죽어있어요! 서버 다시 켜주세요!" 라고 요청하여 해결했습니다.

## 3. 새로고침(F5) 시 404 NOT_FOUND 에러 발생

### 🚨 발생했던 문제

Vercel 배포 후 버튼을 클릭해서 페이지를 이동할 때는 잘 되는데, 특정 페이지(예: `/dashboard`)에서 새로고침을 누르거나 주소를 복사해서 직접 들어가면 Vercel의 404 에러 창이 떴습니다.

### 💡 원인 (SPA 라우팅의 한계)

React 앱은 HTML 파일이 단 1개(`index.html`)뿐인 SPA(Single Page Application)입니다.
리액트 내부(React Router)에서 주소만 바꿔치기하며 화면을 그릴 때는 문제가 없지만, 브라우저 주소창에서 엔터를 치거나 새로고침을 하면 브라우저는 **Vercel 서버에게 진짜로 "dashboard.html 파일 좀 주세요" 라고 요청**해버립니다. 당연히 서버에는 그런 파일이 없으므로 404 에러를 뱉습니다.

### 🛠️ 해결 방법 (`vercel.json` 추가)

프로젝트 최상단 루트 폴더에 `vercel.json` 설정 파일을 하나 만들어서 해결했습니다.
**"사용자가 어떤 주소(`/어쩌구저쩌구`)를 새로고침으로 요청하더라도, 무조건 당황하지 말고 `index.html` 파일을 보여줘라!"** 라고 Vercel에게 룰을 정해준 것입니다.

```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/"
    }
  ]
}
```

이 파일을 추가하고 배포한 이후, 어떤 페이지에서 새로고침을 해도 완벽하게 화면이 유지됩니다.
