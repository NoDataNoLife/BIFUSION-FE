첨부 답변의 **‘추가 가능’은 구현·일정 확정이 아닙니다.** 아래는 취소 6개, 추가 연동 11개를 최신 Medfusion `f473b60`과 FE·BE 코드에 대조한 판정입니다.

## 읽기 전에 알아둘 말

- **Job:** AI 계산 한 건. `job_id`는 계산 식별자입니다.
- **워커:** 뒤에서 계산하는 프로그램입니다.
- **GPU:** AI 계산에 사용하는 장치입니다.
- **S3 bucket/key:** 파일 창고 이름과 그 안의 경로입니다.
- **임시 URL:** 일정 시간만 파일을 열 수 있는 주소입니다.
- **404:** 대상 없음. **409:** 중복 또는 현재 상태와 요청이 충돌함.

PENDING=대기, STARTED=시작, RUNNING=진행, SUCCESS=성공, FAILED=실패, CANCELLED=취소입니다. Celery 내부 FAILURE/REVOKED는 외부 FAILED/CANCELLED로 바뀝니다.

## 회의에서 특히 주의할 5가지

1. **취소 상태 변환만으로는 중단되지 않습니다.** 접수 → 실제 계산 중단 → 상태 기록 → 파일/GPU 정리가 필요합니다.
2. **7일 보존은 제안입니다.** 첨부의 기본1일 설명은 운영 측정 결과가 아닙니다. 보존 기간·재시작·BE 기록을 합의해야 합니다.
3. **진행률100은 완료 증거가 아닙니다.** 최종 파일 저장이 끝난 SUCCESS를 확인해야 합니다.
4. **동시 실행1은 전체1이 아닙니다.** 큐별1이면 세 종류가 동시에 GPU를 사용할 수 있습니다.
5. **현재 저장은 다음 단계 읽기와 별개입니다.** 공유 폴더 또는 S3 다운로드 연결이 필요합니다.

## 기록으로 관리하려면 추가할 것

현재 실패·취소 조회의 진행률은 기본값0입니다. `created_at / updated_at`도 채우지 않아 null입니다. 마지막 진행률, 실제 단계 문구, 갱신시각, 최종 상태 보존을 보완해야 합니다.

실행 중 취소는 계산 반복에서 요청을 확인하고 중단하는 방식이 첨부의 우선 제안입니다. 강제 종료 방식과 구분해 합의해야 하며, 완료와 취소가 동시에 일어나는 상황도 처리해야 합니다.

파일 정리는 **중단 확인 후 해당 작업 폴더만** 대상으로 해야 합니다. 다른 학습 작업이 입력으로 쓰는 이전 증강 파일은 유지해야 합니다.

## 검증할 증거

- 실제 취소 후 GET이 CANCELLED이고 마지막 진행률을 조회할 수 있는지
- 취소 직후 다음 GPU 작업이 성공하고 반복 취소로 메모리가 누적되지 않는지
- 없는 ID와 결과가 만료된 ID를 대기 상태와 구분하는지
- 서버/컨테이너 재시작 후 기록과 파일이 보존되는지
- 실제 증강 파일로 학습하고 그 모델을 분류 워커가 읽는지
- 임시 URL이 만료돼도 bucket/key로 새 주소를 받을 수 있는지
