# BIFUSION AI 연동 — 한눈에 보기

> **이번 목표:** 실제 이미지로 증강 → 학습 → 추론을 끝내고, 새로고침 후에도 결과를 다시 보기.
>
> 2026.10.12 코드 기준 · **GPU 실행 시험 전**

## 1. 우리가 연결할 서비스

![서버별 역할과 현재 연결 상태](assets/01_architecture.png)

**FE는 화면, BE는 서비스 관리, ML은 AI 계산을 맡습니다.** 점선은 추가 연결이 필요한 부분입니다.

## 2. 지금 어디까지 왔나?

| 항목다 | 현재 상태 | 다음 행동 |
|---|---|---|
| AI 코드·API | 있음 | 실제 모델·GPU로 시험 |
| 프론트 화면 | 시안·모의 동작 있음 | 실제 이미지·결과 연결 |
| 백엔드 Job | AI 실행 연결 필요 | 작업·파일·상태 저장 |
| 이미지 제한 | 문서와 검증이 다름 | 공통 제한 정하기 |
| 결과 파일 | S3와 로컬 읽기가 어긋남 | 다음 단계에서 읽기 연결 |

**Job**은 증강 한 번, 학습 한 번처럼 사용자가 실행한 작업 한 건입니다. **API**는 화면과 서버가 요청·결과를 주고받는 통로입니다.

## 3. 이번에 할 일 — 이 순서로

![증강·학습·추론과 결과 전달](assets/02_pipeline.png)

| 순서 | 작업 | 주 담당 | 완료 기준 |
|---|---|---|---|
| ① | RunPod·모델 준비 | ML · FE 협업 | 모델 로딩·GPU 계산 성공 |
| ② | 원본으로 증강 | ML · BE · FE | 실제 새 이미지와 데이터셋 생성 |
| ③ | 학습 → 추론 | ML · BE · FE | 같은 결과를 이어받아 분류 성공 |
| ④ | 화면·Job 연결 | BE · FE | 새로고침 후 상태·결과 유지 |
| ⑤ | 레시피·개미·용량 | 정책 합의 → BE · FE | 실행값·차감·파일 사용량 일치 |

**RunPod**는 GPU 컴퓨터를 빌리는 서비스입니다. **모델 로딩**은 학습된 모델 파일을 읽어 계산 준비를 하는 과정입니다.

## 4. 프론트에서 먼저 바꿀 것

- [ ] 팀원 시안의 **최신 입력값** 반영.
- [ ] 진행률 바·% 제거 → **대기 / 실행 / 성공 / 실패** 유지.
- [ ] 모의 작업·고정 점수 → **실제 Job과 결과** 연결.
- [ ] 별도 Query 업로드 필수 항목 제거 → **완료 데이터셋 선택**.
- [ ] 포크 레시피 → **내 프로젝트·원본 선택 후 증강**.

**Query**는 기존 데이터셋에서 뽑는 분류 연습 이미지입니다. **포크**는 레시피를 내 사본으로 가져오는 것입니다.

## 5. 팀에서 결정할 것

| 결정 | 질문 |
|---|---|
| 실행 재료 | 어떤 외부 코드·모델 파일·GPU를 쓸까? |
| 이미지 제한 | 최소·최대 장수, 용량, 픽셀 크기는? |
| API 형식 | 파일·설정·작업 번호를 어떻게 전달할까? |
| 개미 | 차감·환급·보상은 언제, 어떤 조건으로? |
| 저장 용량 | 사용자별인가 팀별인가? 참조 중인 파일은 어떻게 삭제할까? |

**회의 결정 유지:** 프로젝트 수 무제한 · 저장량 한도 있음 · 진행률 바 우선 제거 · 현금화 제외.

## 6. 첫 시험이 끝났다고 말하려면

- [ ] 실제 원본 → 증강 → 학습 → 추론 성공.
- [ ] 새로고침 후 같은 결과 조회.
- [ ] 실패가 가짜 성공으로 바뀌지 않음.
- [ ] 중복 클릭이 중복 실행·차감으로 이어지지 않음.

작은 설정으로 먼저 **연결**을 확인하고, 품질·속도·비용은 그다음 측정합니다.
