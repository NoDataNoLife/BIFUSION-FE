# BE 최신 응답 연결 (2026-10-23)

로컬 구현 완료. 실서버 FE 배포 및 로그인 사용자 실제 동작 확인은 별도.
RunPod는 10/22 전체 흐름 확인 범위를 유지하며 이번 변경에서 건드리지 않았다.

- 대시보드: /users/me/resource-usage 실제 사용량/기간/누락파일 표시.
  한도 null일 때 비율막대를 표시하지 않는다. 사용량 null은 집계 실패,
  실제0은0으로 표시. 재조회 버튼 제공.
- 프로필: isPublic(콘텐츠 공개)과 isMyPageVisible(프로필 노출)을 구분.
  저장 성공 후 상태 갱신, 조회시 복원. 공개 프로필은 서버 publicActivities를 사용.
- 내 자산의 증강 데이터: 프로젝트 선택 후 /projects/{id}/augmented-datasets 사용.
  datasetId는 증강결과 링크, inspectionTarget.targetId는 신청에 사용.
  inspectionRequestId는 신청자취소에만 사용하고 전문가용 배정ID와 혼용하지 않는다.
  신청/취소/결과 표시, 서버 오류 메시지, 포인트 재조회 연결.
- 리뷰: detail.reviewCount로 대댓글 포함 개수 표시. 목록 totalElements는
  페이징용. 기존 등록/삭제 후 상세·리뷰 재조회 유지. 설정값 null 타입 반영.

## 로컬 검증

프로덕션 빌드, 회귀 테스트26개 통과. 추가파일 ESLint 통과.
검수 신청/취소 테스트는 axios mock이다. 실제 검수나 포인트 차감은 실행하지 않았다.

## 배포 후 확인

1. 사용량 실제0/측정불가/한도null/누락파일 표시와 재조회.
2. 공개활동을 프로필에서 숨긴 뒤 새로고침. 콘텐츠 공개는 유지되고
   본인화면의 저장상태·타인프로필 노출이 일치하는지 확인.
3. 증강데이터 탭에서 프로젝트선택→신청→전문가배정→검토결과 확인.
   담당자와합의하여 포인트가있는 테스트계정으로 수행.
   전문가없음 IS008, 검수시작뒤취소 IS010 등 오류도 성공으로표시하지않는지 확인.
4. 리뷰1개/대댓글1개인 경우 상세리뷰수2, 목록totalElements1 유지.
   등록·삭제후 최신숫자 반영 확인.
