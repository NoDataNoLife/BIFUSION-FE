# BIFUSION 인증 시스템 상세 기술 명세서 (Junior Dev Guide)

이 문서는 주니어 개발자도 이해할 수 있도록 BIFUSION 프로젝트에 적용된 **OAuth2 소셜 로그인 및 세션 관리 로직**을 상세히 설명합니다.

---

## 1. 전체 흐름 요약 (The Big Picture)

우리 프로젝트는 **백엔드 중심의 인증 방식**을 사용합니다. 프론트엔드가 직접 구글에 요청하는 것이 아니라, 백엔드가 모든 인증을 처리하고 프론트엔드에게는 결과(쿠키)만 전달하는 방식입니다.

1. **로그인 시작**: 사용자가 버튼을 누르면 백엔드 주소로 리다이렉트됩니다.
2. **인증 완료**: 구글 인증이 끝나면 백엔드는 브라우저에 **HttpOnly 쿠키**를 심어줍니다.
3. **세션 확인**: 프론트엔드가 켜지면 브라우저에 심어진 쿠키를 백엔드에 보내서 "나 누구야?"라고 물어봅니다.
4. **로그인 완료**: 백엔드가 유저 정보를 주면, 프론트엔드 상태(Zustand)에 저장합니다.

---

## 2. 핵심 기술 포인트 설명

### 2.1 HttpOnly 쿠키와 `withCredentials`

백엔드(`CookieUtil.java`)에서 쿠키를 생성할 때 `.httpOnly(true)` 설정을 사용합니다.

* **보안**: 자바스크립트(`document.cookie`)로 쿠키를 읽을 수 없게 만들어 XSS 공격으로부터 토큰을 보호합니다.
* **전달**: 자바스크립트로 못 읽기 때문에, Axios 설정에서 `withCredentials: true`를 반드시 켜줘야 합니다. 그래야 브라우저가 API를 보낼 때 쿠키를 자동으로 포함해서 보냅니다.

### 2.2 Vite 프록시 (Proxy) 설정

개발 환경에서 프론트는 `3000`, 백엔드는 `8080` 포트를 사용합니다. 포트가 다르면 브라우저는 보안상의 이유로 요청을 막습니다(CORS). 이를 해결하기 위해 프록시를 사용합니다.

---

## 3. 구현된 코드 상세 분석

### 3.1 `useAuthStore.ts` (전역 상태 관리)

Zustand를 사용하여 로그인 상태를 관리합니다.

* **보안 주의**: `isInitialized` 상태나 토큰 정보는 `localStorage`에 저장하지 않습니다(`partialize` 설정). 이는 매 접속 시마다 실제 백엔드 세션을 검증하기 위함입니다.

### 3.2 `App.tsx` (자동 로그인 로직)

사용자가 새로고침을 하거나 사이트에 처음 들어왔을 때, "로그인 상태인지"를 체크합니다. `isInitialized`가 `false`일 때만 실행되어 매 로드 시 세션을 검증합니다.

### 3.3 `OAuth2RedirectHandler.tsx` (콜백 처리)

백엔드에서 구글 로그인이 성공하면 우리 쪽으로 리다이렉트를 시키는데, 이때 추가적인 정보 처리나 페이지 이동을 담당합니다.

---

## 4. 보안 및 예외 처리 (Security & Error Handling)

### 4.1 `ProtectedRoute.tsx` (접근 제어)

* **인증 체크**: 로그인하지 않은 사용자의 대시보드 접근을 차단합니다.
* **온보딩 체크**: 로그인했더라도 닉네임 정보가 없는(온보딩 미완료) 사용자는 자동으로 `/onboarding` 페이지로 리다이렉트합니다.

### 4.2 토큰 자동 갱신 (Silent Refresh)

사용자가 로그인 후 활동하다 보면 Access Token이 만료됩니다. 이때 사용자를 로그아웃시키지 않고 몰래 토큰을 바꿔치기하는 기술입니다.

* **Axios 응답 인터셉터**: 401(Unauthorized) 에러 발생 시 자동으로 `/auth/refresh`를 호출합니다.
* **RTR (Refresh Token Rotation)**: 토큰 갱신 시 새로운 리프레시 토큰을 함께 발급받아 보안을 강화합니다.

---

## 5. 주니어 개발자를 위한 팁

* **500 에러**: 서버 내부 에러입니다. 주로 코드의 오타나 중복된 괄호 `{}` 때문에 Vite가 빌드에 실패했을 때 나타납니다.
* **404 에러**: 주소를 찾을 수 없을 때입니다. API 경로가 중복되지 않았는지 확인하세요.
* **자동 로그인**: 사용자가 로그인 버튼을 안 눌렀는데 대시보드로 간다면, 유효한 쿠키가 남아있기 때문입니다.
