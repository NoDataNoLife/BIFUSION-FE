체크는 코드 구현 기준입니다. 로그인 계정으로 실제 변경 요청을 보내는 QA와 배포는 별도입니다.

## 이미지 API 구분

| 대상 | 현재 실서버 지원 | FE 상태 |
| --- | --- | --- |
| 프로젝트 배경 | PATCH /api/v1/projects/{projectId}/banner, multipart file. 파일 없으면 제거 | 이번 로컬 연결 |
| 레시피 신규 대표 이미지 | POST /api/v1/files/temp → POST /api/v1/community/recipes의 thumbnailFileId | PR #80 연결 |
| 기존 레시피 대표 이미지 변경 | 해당 수정 API 없음 | BE 추가가 필요할 경우 협의 |
| 원본 데이터셋 대표 이미지 | 첨부 이미지 또는 ZIP 첫 이미지 자동 추출, 파일 교체 시 재추출 | 표시 연결. 별도 커버 선택 API는 없음 |
| 증강 데이터 이미지 | ML previewUrl | 표시 연결 |

이미지가 비어 있는 기존 항목은 곧바로 FE 오류라고 판단할 수 없습니다. 원본 파일이 이미지/이미지가 든 ZIP인지, API bannerImageUrl이 null인지, 기존 데이터 보정 작업이 실행됐는지 확인해야 합니다.

- [ ] 기존 레시피의 대표 이미지 변경도 지원할지. 지원한다면 수정 API 필요.
- [ ] 프로젝트 배너는 새 파일 업로드 전에 기존 S3 파일을 삭제하는 코드가 있음. 새 업로드 실패 시 기존 파일 보존하도록 순서/트랜잭션 후 삭제 보완 검토.

별점은 Swagger에서 선택 필드로 보이지만 BE main/develop 서비스에 최상위 리뷰 rating 필수 검증이 남아 있습니다. FE 화면에서는 별점 UI를 완전히 제거하여 순수 댓글/답글 기능으로 동작하도록 복원했으며, BE 호환성을 위해 comment-only 설정에 맞춰 안전하게 요청 페이로드를 전달합니다.
