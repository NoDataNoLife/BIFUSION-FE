## 배포 전 확인

- [ ] BE 담당자가 위 API의 **실서버 배포 완료**를 확인했는지 확인
- [ ] 프론트 브랜치 리뷰·병합·배포
- [ ] 새 API에 대한 CORS/인증 동작 확인. CORS 실패를 프론트에서 우회하지 않음
- [ ] 별점 없는 댓글 등록·수정 허용 여부 확인. 확인 전 `VITE_COMMENT_ONLY_REVIEWS_ENABLED` 기본 false 유지

초대 권한은 새 계약으로 기본 활성화했습니다. 이전 `VITE_INVITATION_ROLES_ENABLED` 플래그에 의존하지 않습니다. 관리자 초대 기능은 BE의 role 저장·수락 적용이 배포된 환경에서 QA해야 합니다.

## 동작상 주의점

- 검수 신청 ID는 inspectionRequestId, 전문가 상세 ID는 inspectionId입니다. 증강 target.id는 AugmentationConfig ID이며 데이터셋 ID로 바꾸지 않습니다.
- 요청 시각은 오프셋 없는 KST도 KST로 해석합니다. 상태별 건수는 필터와 무관한 전체 건수입니다.
- 예전 알림에 invitation 정보가 없으면 수락·거절하지 않습니다. 읽음 상태로 초대 처리 여부를 추측하지 않습니다.
- 비용 조회 실패 시 비용 0으로 간주하지 않습니다. 추론의 비용 확인 버튼은 임시 이미지 업로드를 수행합니다.
- 네트워크 오류·알 수 없는 503은 같은 멱등 키를 유지합니다. 명시적인 ML001/ML006·확정 4xx 거절 후 다음 명시적 실행에는 새 키를 사용합니다. 자동 POST 재시도는 없습니다.
- 재시도 비용이 없는 과거 작업(chargedPoints=null)은 재시도 버튼을 제공하지 않습니다. 설정 화면에서 비용을 확인해 새로 실행합니다.
- 이미지가 없는 경우 종류별 기본 표시를 사용합니다. 레시피 수정 API가 없어 등록 후 썸네일 변경은 지원하지 않습니다.
- 충전 응답이 불명확하면 잔액을 다시 조회합니다. 충전을 자동 재전송하지 않습니다.

## 검증 기록

- TypeScript 및 Vite 빌드 통과
- 기존 + 추가 회귀 테스트 45개 통과: 초대 ID/상태, 페이지 필드, 검수 보상, KST 경고, 예상 비용, 확정 실패/응답 유실 멱등 키 등
- 실제 계정의 초대 응답·앤트 지급·파일 삭제·ML 작업 실행은 이 작업에서 수행하지 않았습니다.
- 기존 Browserslist 데이터 및 번들 크기 경고는 남아 있습니다.
