# 부가 화면 실제 데이터 연결과 QA

기준: 2026-10-21, FE PR #62 병합 후 main에서 분기한 `fix/frontend-live-data`.
BE 계약 기준: origin/main `d000cab`. 확인 시 origin/develop과 파일 내용이 같았다.
실서버 `/api-docs`에 AI 작업·데이터셋·모델·전문가 성과 API가 등록된 것을 확인했다.
인증된 운영 사용자 요청과 모델 계산 성공까지 확인한 것은 아니다.

## 구현

- 홈: 실제 프로젝트·작업 개수 조회. API가 없는 사용량·월간 증강 한도 수치는 제거.
- 자산: BE의 name/totalSize/fileFormats/expertVerified/bannerImageUrl 필드 사용, 페이지 조회.
- 커뮤니티: 실제 목록·검색·페이지·레시피 정렬, 공유 URL로 상세 진입.
- 레시피: 실제 상세·파라미터·리뷰 페이지 조회, 리뷰 작성/수정/삭제/답글, 서버 Fork 저장.
- 데이터셋: 커뮤니티·자산 공통 상세, 실제 파일 다운로드·수정·삭제·검증 결과.
- 활동·프로필: 실제 활동 커서 조회, 타인 프로필 오류 처리, 가짜 신원·활동 제거.
- 프로필: 콘텐츠 공개 여부와 프로필 노출 여부를 분리. 프로필 표시/숨김은 서버 성공 후 안내.
- 알림: 예시 알림 제거, 조회 오류 표시, 실패한 읽음/삭제는 성공으로 처리하지 않음.
  서버 페이지 정보·전체 안읽음 개수를 사용하고 JOB 대상은 실제 프로젝트와 작업 유형을 조회해 이동.
- 전문가: 성과 API 사용, 고정 리워드·순위·만족도 제거. 실제 샘플 이미지·파라미터 사용.
  승인/반려는 PATCH + expertComment로 수정. 실패하면 완료 화면으로 넘어가지 않음.
- Q&A·모집: 가짜 좋아요·미동작 수정 버튼 제거, 전문가만 답변 작성,
  BE의 평면 지원자 필드 사용, 지원 상태 변경 실패 안내.
- AI 작업 목록: 조회 실패를 실제 0개·빈 목록처럼 표시하지 않음.
- Settings는 실제 프로필 계정 설정으로 연결. 비활성 Mock 로그인과 사용하지 않는 Mock 데이터 제거.

## 로컬 검증

- 자동 회귀 검사: `npm test` (기존 AI 8개 + 실제 데이터 연결 12개).
- TypeScript 및 Vite 프로덕션 빌드.
- 검사 전용 로컬 API 서버로 브라우저 확인. 운영 API와 별개이며 테스트용 데이터 사용.
  - 홈에 응답 프로젝트와 상태 개수 표시.
  - 자산의 0 B/0개가 임의의 크기·개수로 바뀌지 않음.
  - 데이터셋 상세 진입, 파일이 없으면 다운로드 버튼 비활성화.
  - 레시피 상세 설명·0점·실제 설정 표시, 빈 리뷰 목록.
  - 리뷰 작성 후 서버 재조회로 작성 내용 표시.
  - 서버 503 시 예시 게시물 대신 오류 표시.
  - 프로필의 실제 정보와 빈 활동·프로젝트 목록 표시.

## 지원 범위와 남은 실서버 QA

- BE는 현재 증강 데이터 검수 신청만 지원한다. 레시피/일반 데이터셋 신청 버튼은 노출하지 않는다.
  기존 검증 결과는 서버에서 제공한 경우 표시한다.
- Q&A/모집 수정·좋아요 API가 없어 작동하지 않던 버튼을 제거했다.
- 사용량·한도 API가 없어 관련 고정 통계는 표시하지 않는다.
- 자산 검색은 현재 서버 페이지에서 수행하며 UI에 범위를 표시했다.
- FE 변경 배포 후 실제 계정으로 자산 등록·상세·수정·삭제·Fork·리뷰·모집 지원·알림을 검증한다.
- 작성자/타인/인증 전문가 계정으로 권한·실패·새로고침을 점검한다.
- 실제 이미지로 업로드→증강→학습→추론 및 S3 다운로드를 검증한다.
- AI 실패 작업 재실행·취소 버튼은 이전 범위와 마찬가지로 별도 과업이다.
- 자동 검사와 로컬 브라우저 통과를 실제 운영 환경 전체 성공으로 간주하지 않는다.
