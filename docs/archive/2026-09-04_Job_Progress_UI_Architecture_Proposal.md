# [기능 제안] AI 작업(증강/학습/추론) 진행률 연동 아키텍처 및 API 규격 제안

## 1. 개요 및 배경
- **목적:** AI 작업(데이터 증강, 모델 학습, 모델 추론) 실행 시 프론트엔드 진행률 UI(`ProgressPage`)에 실시간 진행 상황을 안정적으로 표시하기 위한 연동 방식을 정의합니다.
- **현황:**
  - `BIFUSION-ML` (FastAPI + Celery)에서 비동기 태스크 실행 후 `GET /{job_id}`로 `{ status, progress, result, error }`를 제공하고 있습니다.
  - BE에서 진행률 전달 방식으로 **주기적 조회(Polling)**와 **실시간 전송(SSE)** 중 어떤 방식을 채택할지 논의가 필요합니다.

---

## 2. 기본 전제 사항 (공통 필수)
> **"BE가 ML 서버의 상태를 주기적으로 확인하여 DB(`job` 테이블)에 최신화하는 작업은 필수입니다."**
- **이유:**
  - 사용자가 작업 진행 중 **새로고침(F5)**을 하거나, 다른 탭으로 이동했다가 복귀하는 경우
  - 프로젝트 상세 페이지나 마이페이지의 **작업(Job) 히스토리 목록**에서 상태를 조회해야 하는 경우
  - SSE 스트림 연결이 일시적으로 끊겼을 때 현재 진행률을 즉시 복구해야 하는 경우

---

## 3. 연동 방식 비교 (Polling vs SSE)

| 비교 항목 | 1️⃣ 주기적 폴링 (Polling, 1.5초) ⭐ 권장 | 2️⃣ 실시간 SSE (Server-Sent Events) |
| :--- | :--- | :--- |
| **작동 방식** | FE가 1.5초 주기로 `GET` API 반복 호출 | BE가 HTTP 연결을 유지하며 이벤트 발생 시 Push |
| **구현 복잡도** | **매우 낮음** (표준 REST API 활용) | **보통** (서버 측 `SseEmitter` 수명 주기/타임아웃 관리) |
| **인프라 영향** | 기존 설정 그대로 사용 가능 | **Nginx 추가 설정 필수** (`proxy_buffering off;`, `timeout` 연장) |
| **네트워크 안정성** | **매우 높음** (일시적 단절 시 다음 주기에 자동 복구) | **연결 끊김 관리 필요** (네트워크 지연/모바일 백그라운드 시 재연결) |
| **사용자 경험** | 1.5초 간격이면 충분히 실시간처럼 부드러움 | 1% 단위의 초정밀 실시간 애니메이션 가능 |
| **새로고침 복구** | F5 새로고침 시 즉시 현재 진행률 복원 | 재연결 전까지 공백 발생 가능 |

---

## 4. 단계별 권장 구현 전략

### 🚀 1단계: REST API 기반 주기적 폴링 (빠르고 안전한 1차 연동)
1. **BE:** ML 서버 상태를 주기적으로 조회하여 `job` 테이블(`status`, `progress`) 갱신
2. **BE:** 단건 작업 상태 조회 API 제공 (`GET /api/v1/jobs/{jobId}`)
3. **FE:** 1.5초 간격으로 `GET` 요청을 폴링하여 진행률 바 및 상태 텍스트 갱신
4. 👉 **장점:** Nginx 버퍼링 이슈나 연결 끊김 없이 가장 빠르고 안정적으로 배포 가능

### 🚀 2단계: SSE 스트림 고도화 (하이브리드 안심 설계)
1. 1단계 연동 및 검증 완료 후 실시간성을 극대화하기 위해 `GET /api/v1/jobs/{jobId}/stream` (SSE) 추가
2. 평소에는 SSE로 부드러운 1% 단위 실시간 수신
3. 네트워크 불안정으로 SSE 연결이 끊어지면 1단계의 폴링(`GET`)으로 자동 전환되는 하이브리드 구성

## 5. 프론트엔드 요구 데이터 규격 (DTO)

### `GET /api/v1/jobs/{jobId}` (또는 각 도메인별 조회 엔드포인트)

```json
{
  "jobId": 101,
  "jobCode": "JOB-AUG-001",
  "type": "AUGMENTATION",
  "status": "RUNNING",
  "progress": 65,
  "currentStep": "Anomaly 클래스 이미지 생성 중... (45%)",
  "result": null,
  "error": null
}
```

### 필드 상세 설명
- **`status`** (String, 필수): `PENDING` (대기), `RUNNING` (진행 중), `COMPLETED` (완료), `FAILED` (실패), `CANCELLED` (중단)
- **`progress`** (Integer, 필수): 0 ~ 100 사이의 진행률 백분율
- **`currentStep`** (String, 선택): 진행률 바 하단에 노출할 세부 안내 문구 (예: "파라미터 로드 중...", "모델 학습 중...")
- **`result`** (Object, 완료 시 필수): `COMPLETED` 시 결과 페이지 이동에 필요한 결과 데이터 또는 결과 ID
- **`error`** (String, 실패 시 필수): `FAILED` 시 에러 모달/안내창에 노출할 원인 메시지
